# G0401 exact-APK OTA audit — 2026-09-11

## Scope

Static/offline audit of the preserved official Android MyQ 5.243.1.73243 smali tree. No Android component was invoked and no Chamberlain/MyQ request was sent.

## G0401 Smart Garage Hub path

The Smart Garage Hub firmware/setup helper does not expose or invoke a firmware download/start endpoint. Its flow refreshes the normal device list through `DeviceApi`, resolves the already-known device from `deviceManager`, reads `myq.sdk.data.model.q.b0()`, and maps the JSON field `mandatory_update_status` to an enum. Missing state becomes `NOT_REQUIRED`.

So the app-side G0401 path is:

```text
Smart Garage Hub firmware/setup UI
  -> normal DeviceApi refresh
  -> existing device DTO
  -> mandatory_update_status
```

not a firmware manifest/download flow.

## Firmware fields in the generic device DTO

The exact APK contains `latest_available_firmware_version`, `firmware_available`, and `firmware_version` in `com.chamberlain.network.framework.model.deviceservice.b`. Their observed use in that model is serialization/access/equality/hash/toString state. This alone does not identify a G0401 OTA transport.

`vkp_current_firmware_version` is a SharedPreferences key. The code writes/reads it around device polling/setup and camera/video-keypad firmware bookkeeping. It is not a URL or firmware blob location.

`myq_firmware_version` is emitted by tracker mapping code as telemetry.

## Real firmware transports found in the APK

Exact Retrofit-route filtering found two firmware families:

1. **Lock firmware** under `api/{apiVersion}/accounts/{accountId}/devices/locks/{serialNumber}/...`, including `/firmware`, `/firmware/complete`, and `/prepare_firmware`. The corresponding service is explicitly the v6 lock service and uses lock model types.
2. **Tend/CXS camera firmware** under `cxs/api/devices/{deviceId}/hw/firmwareInfo` and `cxs/api/devices/{deviceId}/hw/do/startFirmwareUpgrade`. The only `startFirmwareUpgrade` caller is `features/places/devices/camera_firmware_update`. The associated SDK code logs `Attempt ... to wake up camera`, uses Tend session IDs, and the model class contains `$cameraStatus` handling.

These are real firmware APIs in the app, but they are not evidence of a G0401 firmware endpoint.

## Conclusion

For MyQ 5.243.1.73243, no G0401-specific firmware manifest, firmware download URL, firmware-start route, or app-managed G0401 firmware payload was found. The Smart Garage Hub path consumes update status already present in normal device state. The visible firmware APIs belong to cameras/Tend devices and locks.

This closes the current exact-APK OTA lane as a source of a G0401 firmware binary unless a future APK adds a new route or device class. The next software-only lane is passive natural G0401 destination observation, with emphasis on previously unseen DNS/HTTP(S) destinations rather than the already-known `connect.myqdevice.com` / `connect1.myqdevice.com` connection service.

## Safety boundary

Do not call the camera or lock firmware endpoints against the G0401. Do not trigger firmware checks/updates, reset/re-pair, or setup mode merely to generate traffic. Passive observation and offline analysis remain the next step.
