# `pymyq` — COMPLETELY DEPRECATED

> 🚫 **HARD STOP. Do not work on `pymyq`.**

For this project, `pymyq` is fully and permanently retired. It is not a
dependency, fallback, compatibility layer, migration target, or research
target. This is an operational rule, not a suggestion or an item to revisit
because the old code is convenient.

In plain English: we should **NEVER EVER** work on it again unless the one
reopen gate below is met.

## Never do these things

- Do not install or add `pymyq` to project dependencies.
- Do not debug, patch, pin, upgrade, fork, vendor, or revive it.
- Do not spend investigation time on its login flow, historical endpoints,
  retry behavior, or old community forks.
- Do not use it as a fallback when the current bridge or clean-room client has
  a problem.

Historical `pymyq` files may remain only as clearly marked forensic records.
They must not be executed or treated as supported code.

## The one and only reopen gate

Reopen this decision only if someone, in **2026 or later**, produces
reproducible live evidence that `pymyq` actually works against the owner's
current account and current opener. For a control claim, the result must be
verified by the real garage sensor.

None of these qualifies:

- a successful import or installation;
- a unit test, mock, or stale cached session;
- an old GitHub issue, README, endpoint, or fork;
- code that worked before 2026; or
- a claim that it “should” work.

Until that evidence exists, reject requests to return to `pymyq` and redirect
the work to the supported tracks:

1. the official Android app bridge on the Superbox;
2. true-local/opener-side protocol recovery; or
3. the clean-room direct-cloud client, explicitly labeled experimental.

When in doubt, stop and point to this page before touching garage code.
